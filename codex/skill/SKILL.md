# pm-flow

插件目录：`__PM_FLOW_ROOT__`。用该目录下的 `tools/pmw.mjs` 管理工作区；
不要直接修改需求状态文件。通过 `node <pmw路径> <命令> --json` 调用。

首次处理需求前运行 `setup status`。如果配置未完成，只询问缺失的选项：
已有需求工作区父目录、是否启用研效通、是否启用 Obsidian。分别使用
`setup set --workspace <绝对目录> --yxt on|off --obsidian on|off`
保存用户明确给出的选项。允许暂不启用集成，后续可以修改。不要要求用户
在聊天中提供密钥。启用研效通时引导用户通过本机既有方式登录；启用
Obsidian 时引导配置 Local REST API 和宿主环境变量 `OBSIDIAN_API_KEY`。
配置完成不等于认证成功；需要使用时检查实际连接。关闭的集成不调用。

先运行 `board` 查找需求，再对对应目录运行 `status --dir <目录>`。
每次继续处理、作出进度判断或写入前重新读取 `status` 和 `since`；
工作过程中用户可能随时从看板修改，写入前再次读取。按需用 `guide`
读取阶段指引，调用 pmw 命令更新状态并遵循门禁。
需求类型、负责人或业务规则不明确时不要编造。

完整工作流程和研效通使用方式参考插件目录中的 `SKILL.md`；其中
`pm_flow`、`pm_role` 等是 DeepSeek Harness 专用工具，Codex 使用可用工具
完成等价操作，不能假定能够派子 agent。研效通写入前展示目标和内容，
遵循用户授权；问题单先准备并展示确认稿，经确认后再提交。

本机看板由插件目录的 `codex/server.mjs` 提供；需要时启动并在
`http://127.0.0.1:47831/` 打开。看板的修改供 AI 下次读取，不能向空闲
对话主动推送实时通知。
